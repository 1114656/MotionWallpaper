## 变更

- 系统原画播放首次报告 `0xC00D5212` 时，在 Renderer 内回退到随包 FFmpeg 的 HEVC/H.264 解码；不向 Windows 安装解码器，不创建性能副本，不修改原文件。
- 硬解与呈现共享 D3D11 设备，GPU NV12/P010 转换为 SDR 桌面画面，多屏共用解码结果；软件兼容路径有 1080p 像素量和 60 FPS 预算。
- 高帧率源允许跳过非参考帧，避免把可丢弃的 240 FPS 帧全部送入 GPU；仍保留参考帧依赖。持续落后超过 3 秒明确报错，交由已有原画恢复提示处理。
- 修正 MOV 容器与流内色彩标签冲突、有限/全范围、色度位置、旋转、HDR 显示转换。界面显示“内置解码器 · GPU 硬件解码”或 CPU 路线及失败原因。

## 实测

GTX 1070 / 582.66，Ryzen 7 5700X，两块 3840×2160 显示器（60 Hz / 59.997 Hz）。当前用户未安装 Windows HEVC 扩展。隐藏测试窗口不改桌面、已安装设置或媒体库。

- 完整发布构建通过，119 项原生测试通过，无编译警告/错误。新增验证包含 CPU/WARP 像素转换、循环、暂停时钟、释放解码器后按位置恢复、损坏输入；既有双屏协议测试新增随包解码自动/软件路线。
- 安装目录中的完整森林原片：HEVC Main10，4K、240 FPS，MOV 容器 P3/Gamma 2.2。自动从 Windows 失败回退到随包 GPU 解码，首帧约 0.516 秒；两段约 10 秒观测窗口中的呈现进度均为 60.0 帧/秒。此值来自渲染呈现计数，不是显示器光学测量，也不是解码器只处理 60 个参考帧的承诺。
- 同一进程双屏播放、冻结、暂停、继续、正常退出通过。10 秒无重编码片段已跨循环边界播放；完整原片另做约 30 秒播放状态测试，未声称完成整片/全天稳定性认证。
- 完整原片测试工作集约 241.1 MiB，峰值约 241.8 MiB；私有提交约 877.7 MiB。前者不能代表全部内存或显存；4K HEVC 参考帧、驱动和双屏呈现仍有明显成本，性能副本仍适合日常省电播放。
- 移除测试目录的 FFmpeg 库后，系统 H.264 路线仍能播放；HEVC 明确返回缺少解码器错误，进程正常退出。
- 显式 CPU 解码 4K240 原片被预算拒绝，不允许悄悄降低原画分辨率或无限占用 CPU。

## 色彩对照

测试宿主通过生产 `BuiltinVideo::Draw` 渲染，再读回 BGRA；播放器本身不做此 CPU 读回。参照为 FFmpeg/zimg，使用明确输入色彩标签、`agamma=0`、线性光处理、sRGB 输出。HDR 比较采用相同的 Reinhard 映射与 1000 nit 峰值。旋转参照先完成色彩转换再旋转，避免改变色度采样位置。

| 输入 | RGB 平均绝对误差（0–255） | 99% 分位误差 |
| --- | ---: | ---: |
| 实际 4K P3 MOV | 0.421 | 1 |
| HEVC Main10 SDR | 0.209 | 1 |
| HEVC Main10 PQ | 0.613 | 3 |
| HEVC Main10 HLG | 0.556 | 1 |
| 90° 容器旋转 | 0.209 | 1 |
| 全范围 Main10 | 0.250 | 1 |

五个小型素材的硬解/CPU 画面平均差异小于 0.1/255。双线性 GPU 采样与 CPU 参照插值不同，高对比色块边缘存在较大的个别差异，以上指标不代表逐像素完全一致或专业色彩认证。P3、HLG、旋转对照也进行了图片检查。

验证日志及图像位于本机 `<本地验证目录>\builtin-hevc-20260923`。可通过测试宿主复现单帧输出：

```powershell
& .\native\x64\Release\MotionWallpaper.Tests\MotionWallpaper.Tests.exe --probe-builtin '<源视频绝对路径>' '<输出BMP绝对路径>' hardware 0
```

软件路径把 `hardware` 换为 `software`；最后一个参数是起始秒数。完整自动测试仍由 `scripts/build-native.ps1` 执行。

## 验收边界

仍要求系统基础 Media Foundation，Windows N 需要 Media Feature Pack；本改动解决缺少 HEVC 解码器，不替代整个 Windows 媒体框架。此版输出 sRGB SDR，不支持 HDR 直通或 Dolby Vision。8K/高帧率、Intel、AMD、混合显卡、不同驱动和长时间运行尚未完成实机矩阵认证。安装包仍未代码签名。

用户更新时沿用原安装目录覆盖安装，不要先卸载：原卸载行为会清理安装目录内的默认媒体库和配置。这里的测试与打包不会自动替换用户现有安装。
