# 0.2.0 生成提速与本机验收

本次按“生成尽快、播放省电”的约定调整转码，不增加断点续编码、分段拼接或新的设置项。版本号为 0.2.0，先提供本地安装包与便携包供用户验收；没有推送标签或公开发布 GitHub Release。

## 实现

- FFmpeg 使用普通进程、普通内存优先级，显式退出执行速度 EcoQoS。播放进程的节能策略保持独立。
- 滤镜线程由固定 2 个改为按逻辑处理器数分配，留出调度空间，最高 12 个；CPU 编码最高 8 个线程，输入软件解码仍限制 4 个线程，避免无限扩大解码帧缓冲。
- 已明确标记为 8-bit BT.709、有限范围、4:2:0、无需旋转、保持宽高比且不放大的输入，优先使用同一 GPU 的硬解、缩放和硬编。NVIDIA 使用 CUDA Lanczos 缩放，CUDA 设备通过隔离子进程查询 LUID，与选定 DXGI 设备匹配；不假设两个 API 的设备序号相同。Intel/AMD 路线通过各自 QSV/D3D11 缩放预检，失败时保留兼容路线。
- P3、HDR、10-bit、需要裁切/旋转或缺少完整色彩标记的输入继续使用明确的兼容转换，保留 SDR 色调映射、色域转换及 8-bit 抖动。本次没有采用实验性 Vulkan 色彩转换路径。
- 快速路线执行短片段预检、输出规格和 Windows 实际首帧检查；失败可回退到原有硬解加 CPU 滤镜路线，再按既有预算尝试软件解码或其他编码器。完整输出仍须由优化器验收后原子发布。
- 等待性能副本时沿用高清静态画面与视频渲染停止屏障。平衡副本匹配显示器分辨率和刷新率，不再额外加 30 FPS；共享解码和各屏独立呈现策略保留。
- UI 的“暂停 / 继续”调整为“停止 / 重新生成”，明确停止后会从头生成，原视频保留。没有断点续编码承诺。

## 实测

机器：Ryzen 7 5700X，8 核 16 线程；GTX 1070，驱动 582.66。

输入：用户森林 MOV 的约 10 秒片段，3840×2160、240 FPS、HEVC Main10，P3 / gamma 2.2 SDR。目标保持 3840×2160、60 FPS、H.264、8-bit BT.709 SDR。

| 相同片段与目标 | 墙钟时间 |
| --- | ---: |
| 修改前，生产转码函数（含候选预检） | 45.421 秒 |
| 修改后，生产转码函数（含候选预检） | 28.708 秒 |

这次单次对比缩短约 36.8%，约为原速度的 1.58 倍。它不是整段 243 秒视频的计时，也不包含优化器最终缓存发布；不能据此保证所有机器或视频都有相同收益。输出完整解码得到 604 帧，平均及标称帧率均为 60/1，Windows 首帧检查通过；输入原文件 SHA-256 未变化。

另用已经规范化的 8-bit BT.709 4K 视频测试 1080p60：快速路线实际选择 NVIDIA CUDA 缩放，成功完成；测试主动拒绝第一个短片段后，第二次兼容路线通过。两份输出均为 H.264 / yuv420p / BT.709 limited / 1920×1080 / 60 FPS，完整解码 604 帧，Windows 首帧检查通过，源文件未修改。

前期仅滤镜图实验中，2 个 CPU 滤镜线程为 31.620 秒，12 个为 21.385 秒，带额外传输的 GPU 色彩实验为 21.229 秒。后者没有足够收益支持引入新色彩管线，因此本版保留已经验证的色彩处理。

## 验证与边界

- `scripts/build-native.ps1`：118 项原生测试通过，编译零警告、零错误。
- `scripts/test-video-pipeline.ps1`：SDR、PQ、HLG 10-bit MOV、90° 容器旋转 MOV 四种输入全部通过；检查完整输出解码、尺寸、帧率、时长、色彩、亮度异常及源哈希。
- `scripts/test-video-gpu-scaling.ps1 -Source <规范 BT.709 片段> -RequireGpuScale`：真实 GPU 路线与拒绝预检后的兼容回退通过。此脚本针对具备所需硬编能力的测试机，不能代替完整硬件矩阵。
- 本次实机覆盖 GTX 1070 / 582.66。Intel、AMD、混合显卡、多代驱动和干净 Windows 10/11 环境尚未完成认证。
- 包未代码签名，SmartScreen 可能提示；没有进行公开发布。暂停后续传、大规模用户验证及全 GPU HDR/P3 色彩转换不在本版完成范围内。

安装包与便携包由发布脚本验证版本资源、工具链、许可证、语言和内容排除规则，并生成各自的 `.sha256` 文件。安装升级验收结果见同目录发布记录。
