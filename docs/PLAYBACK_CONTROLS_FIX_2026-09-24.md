# 托盘暂停与副本任务状态修复（2026-09-24）

> 本文记录最初的恢复命令方案。随后按用户要求改为托盘与设置共用持久化开关，当前行为与验证见 [共享播放状态与自动生成](SHARED_PLAYBACK_AND_AUTO_OPTIMIZATION_2026-09-24.md)。

## 原因

- 托盘暂停保存在 Agent 的 `TrayControlState` 中；设置页只保存 `activePlaybackEnabled`，没有发送解除手动暂停的指令。因此关闭再开启活动播放也无法覆盖托盘暂停。
- 本机两个视频目录均有 `.optimization-cancelled`，且没有活动请求或完成的副本。后台尊重取消记录，不再自动生成；界面却显示“未生成”和“到任务页查看任务”，没有解释为什么任务列表为空。

## 修改

- 增加幂等 `resume-playback` 运行时命令。用户开启活动播放或桌面播放时，先保存设置，再解除手动暂停。普通设置保存不解除暂停，运行状态卡片另有“恢复壁纸”入口。
- Optimizer 将取消、停止、删除及失败原因传递到每屏运行状态。缺少性能副本时显示“静态预览”和对应原因，提供“重新生成”入口。
- 存储页显示“已取消 · 不会自动生成”。主动重新生成使用新的持久化任务标识，清除取消记录；同一档位已有活动任务时不重复创建。后台未运行时会启动后台服务。
- 保留之前的暂停资源释放修复，未改变原片、画质策略或用户的取消决定。
