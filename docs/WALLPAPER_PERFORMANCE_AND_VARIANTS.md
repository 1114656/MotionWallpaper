# 壁纸性能档位与优化副本设计

> 状态：核心策略、独立管理页、真实转码进度百分比与运行时实际文件标识已实施
> 记录日期：2026-08-25

本文定义 MotionWallpaper 的三个性能档位、混合显示器选择规则、后台副本任务，以及独立的“存储与节能优化”管理页面。自动平衡、低功耗与软件播放兼容文件都使用 `v5` 策略标识；内部兼容副本仍以独立的 `cpu-smooth` 前缀隔离。旧策略文件只参与安全迁移，不作为长期可见的历史副本保留。

## 设计目标

优先级固定为：

1. 画面清晰、播放流畅。
2. 切换过程中不出现黑屏、Windows 静态壁纸或旧媒体。
3. 在前两项成立后降低 CPU、GPU、显存、内存和磁盘占用。
4. 所有降级必须来自用户明确选择，不允许因电池状态暗中切换档位。

“不降低画质”需要区分两种含义：

- **源文件无损**：只有直接播放源文件才能保证显示链路不重新编码；导入文件本身始终逐字节保留，任何优化或兼容副本都另写新文件，不改变源文件的分辨率、帧率、码率和色彩信息。
- **显示结果接近原画**：优化副本会重新编码，不是数学意义上的无损；目标是在对应显示器上肉眼难以察觉差异。

## 三个性能档位

### 原画优先

- 始终直接播放导入的源文件。
- 不创建、不选择优化副本。
- 保留源分辨率、源帧率、源码率、色深、色域和 HDR 信息。
- 4K 视频在 2K 显示器上仍解码 4K，再由呈现链路缩小，保留超采样优势。
- 这是质量最高、功耗也最高的档位。
- 用户删除源文件后，该档位不可用；应用不会用优化副本冒充原画。

界面文案应使用“完全使用源文件”，不使用“码率最高”。源文件码率不一定是所有文件中最高，关键是没有重新编码。

### 自动平衡

- 目标分辨率由正在使用同一媒体的显示器决定。
- 不超过源视频分辨率，禁止放大低分辨率源视频。
- 目标帧率最高为 120 FPS，但不生成显示器无法展示的多余帧。
- 保留源文件的宽高比、色深、色彩空间和 HDR 信息。
- 已确认是普通 8-bit SDR 的素材采用高质量 H.264 High `avc1`；必须保留 HDR 或高位深时只尝试硬件 HEVC Main10 `hvc1`，无法安全保留则继续使用源文件。目标是在目标显示器上肉眼接近源文件。

目标帧率规则：

```text
目标帧率 = min(源帧率, 120, 使用该媒体的显示器最高刷新率)
```

示例：

| 源视频 | 显示器 | 自动平衡结果 |
| --- | --- | --- |
| 4K 240 FPS | 2K 60 Hz | 2K 60 FPS |
| 4K 240 FPS | 2K 165 Hz | 2K 120 FPS |
| 4K 120 FPS | 4K 144 Hz | 4K 120 FPS |
| 2K 60 FPS | 4K 144 Hz | 2K 60 FPS，不放大、不插帧 |

### 低功耗

- 分辨率匹配正在使用该媒体的显示器实际需要。
- 不超过源视频分辨率，禁止放大低分辨率源视频。
- 目标帧率最高为 60 FPS，不对低帧率源视频插帧。
- 保留宽高比、色深、色彩空间和 HDR 信息。
- 优先使用硬件解码和适合该显示器的低功耗适配器。

目标帧率规则：

```text
目标帧率 = min(源帧率, 60)
```

示例：4K 240 FPS 视频在 2K 显示器上生成 2K 60 FPS 副本。它会放弃 4K 缩小带来的少量超采样优势，但显著减少解码像素和帧数。

### 软件播放兼容副本（内部）

`cpu-smooth` 不是第四个用户档位，也不是保真画质副本。显式选择软件解码，或 `auto` 模式无法为当前源编码、profile、位深输出格式和分辨率找到可用的物理 D3D11 解码配置时，Agent 才按处理器逻辑核心数和显示器需求选择 1080p60、720p60、720p30 或 480p30 上限。探测选中的物理适配器以 LUID 约束 Renderer，确保多显卡机器的能力判断和实际解码设备一致。该结果按源文件缓存，并在显示拓扑或显卡变化后重新探测。为了改善软件播放的流畅度与兼容性，未带 HDR 传递函数且非 BT.2020 的 SDR 素材（包括普通 SDR 10-bit）可以转换成 8-bit SDR H.264 `avc1` 副本；HDR、BT.2020，以及带 HDR 色彩标记的高位深素材一律跳过 `cpu-smooth`。转换只写入 `cpu-smooth-...-v5.mp4`，导入源文件永不改写。它与同为 v5、但前缀不同的画质档位文件不能互相冒充或硬链接复用。

## 电池行为

- 删除“自动平衡在电池供电时暗中变成 60 FPS”的行为。
- 用户选择的播放档位在插电和电池供电时保持一致。
- 如果以后需要自动节能，新增独立的“使用电池时切换到低功耗”开关，默认关闭。
- 后台生成任务可以在电池供电时暂停，但必须在“存储与节能优化”页面明确显示“等待接通电源”，不能伪装成档位已经生效。
- 副本尚未完成时，动态屏保仍可安全播放现有媒体；用户活动时的桌面播放等待当前性能档位副本完成，避免源文件回退绕过所选性能限制。

## 多显示器规则

同一媒体只选择一个足以覆盖所有目标显示器的副本：

```text
目标分辨率 = 使用该媒体的所有显示器中所需的最高分辨率
```

- 2K + 1080p 显示器播放同一媒体：使用 2K 副本，1080p 输出独立缩小。
- 4K + 2K 显示器播放同一媒体：使用 4K 文件，2K 输出独立缩小。
- 不同显示器播放不同媒体：分别选择各自所需的源文件或副本。
- 不同显卡适配器仍可拥有独立呈现链路，但同一适配器上的相同媒体应共享一次解码。
- 每块显示器始终拥有与自身物理尺寸一致的输出表面，不能用巨型虚拟桌面表面代替。

目标尺寸需要保持视频宽高比并满足 `UniformToFill`；不能拉伸变形，也不能超过源视频尺寸。

## 副本生成与选择

### 导入

- 导入永远先逐字节保存源文件，立即生成封面并加入媒体库。
- 当前档位为“原画优先”时不创建副本任务。
- 当前档位为“自动平衡”或“低功耗”时，根据当前显示拓扑创建一个对应任务。
- 任务在后台低优先级执行，不阻塞导入窗口和壁纸播放。

### 快速切换档位

- 每个媒体同时最多有一个活动生成任务。
- 相同参数的重复请求直接合并。每次新请求写入 `mode|requestId`，进度文件携带同一 requestId。
- 用户连续切换档位时执行“最后请求生效”，取消尚未完成的过期任务。完成、失败与清理都必须在文件句柄锁内精确匹配档位和 requestId，因此同档位取消后立即重试也不会被旧工作线程误清。
- 自动平衡和低功耗各自最多保留一个完整副本；切换档位不删除另一档，但同档新规格完成后会清理旧规格。
- 页面顶部仅在存在任务时显示任务区，并同步显示排队、等待电源、生成中或已暂停；生成中展示 FFmpeg 报告的真实百分比进度。
- 暂停会立即停止本次编码并删除不可续传的 `.part` 文件，同时保留任务请求；继续时从头安全生成。
- 取消会删除任务请求、暂停状态和本次 `.part` 文件；已经完成的正式副本不受影响。
- 每次编码尝试使用独立高熵 token 的 `.part` 文件；取消、失败或程序退出后不得留下可选中的半成品。外置媒体库的临时文件、最终原子发布和裁剪均使用本次启动校验得到的 Volume GUID 稳定路径，不在可被复用的盘符别名上写入。

### 使用与交接

- 没有目标副本且没有对应生成任务时，可以继续播放仍然存在的源文件或兼容已有副本；当前档位任务进行中时，用户活动下的桌面播放报告暂不可用，动态屏保仍可使用安全回退。所有可播放文件都不存在时明确报告不可用。
- 新副本必须通过容器、分辨率、帧率、时长、可解码性和文件大小校验。
- 新 Renderer 完成首帧 ACK 后才能替换旧 Renderer。
- 旧画面保留到新首帧被 DWM 提交，切换过程中不能出现空白或系统静态壁纸。
- Runtime 状态必须记录实际播放路径和实际档位，UI 不能只显示用户期望值。

### 编码质量

- 对用户选择的 `balanced` / `power-saver` 画质副本，只有压缩 subtype 与 profile 能正向确认是 8-bit 的普通 SDR 素材才生成 H.264 High `avc1`；按具体 DXGI 适配器及显存排序逐卡尝试 NVIDIA NVENC、Intel Quick Sync、AMD AMF，不再把同厂商的多块显卡合并成一个候选；硬件后端不可用时再使用随包提供的 OpenH264。Unknown、VP9/AV1 高位深或缺失 profile 的素材不得仅凭“没有 HDR 标记”推断为 8-bit。这样不会依赖 Windows 可选 HEVC 解码器，也不会静默压低未知素材的位深。
- 对 `balanced` / `power-saver`，HDR、BT.2020 或不允许安全转成 8-bit SDR 的高位深素材仅尝试硬件 HEVC Main10 `hvc1`，保留源色彩元数据；无法安全保留时放弃副本并使用源文件。
- 每个 FFmpeg 候选都必须匹配预期编码格式，并由 Media Foundation 实际解出首帧后才能原子发布；某一后端初始化、输出校验或本机解码探针失败时自动尝试下一安全后端。
- 软件任务限制在最高 2560×1440/60 FPS、最多 2 个编码线程，避免普通电脑长时间满负载。
- 用户画质副本在 HEVC Main10、HDR、BT.2020、已知或无法确认的高位深、4K/60 或 2K/120 等高负载目标没有安全后端时，保留并播放源文件，不暗中降为 8 位、SDR 或更低档位。独立的 `cpu-smooth` 是有明确边界的兼容性例外：普通 SDR 10-bit 可以生成 8-bit SDR H.264 副本，但源文件仍保持不变，HDR、BT.2020 或带 HDR 色彩标记的高位深素材不生成该副本。
- 不插帧、不锐化、不添加画面增强，不伪造源文件不存在的细节。
- 编码参数需要通过固定素材 A/B 测试后确定，不能只依赖一个无上限的 CQ 参数。
- 生成文件明显大于源文件时应重试受限参数；仍不合理则删除候选，并继续使用仍然存在的源文件或兼容副本。
- 每个档位最多保留一个当前版本。编码策略或目标分辨率变化时，先完成并校验新文件，再切换使用并清理同档旧文件。

建议的缓存键：

```text
源文件内容哈希 + 档位 + 目标宽高 + 目标帧率 + 编码策略版本
```

## 独立“存储与节能优化”页面

副本属于全局存储和播放性能，不属于某一个壁纸分组。分组页面只负责展示、选择、重命名、移动和删除壁纸；生成、取消和删除副本从分组菜单中移除。

### 导航入口

在左侧边栏增加一个全局入口，位于“系统设置”下方、“壁纸分组”上方：

```text
Motion

系统设置
存储与节能优化

壁纸分组
  海景
  我的壁纸

固定媒体库
```

系统设置中的“壁纸性能”下拉框继续负责选择全局播放档位；“存储与节能优化”页面只负责查看任务、比较文件和管理缓存，避免同一设置在两个页面重复出现。

### 页面布局

原画不是副本，因此第三列应命名为“源文件”，不能写成“原画副本”。任务和文件管理分成上下两层：顶部任务区按需出现，底部使用按媒体排列的横向卡片：

```text
存储与节能优化                                总占用 3.7 GB
管理后台生成任务和已完成的性能文件             [清理过期副本]

生成任务（仅有任务时显示）
[封面] 山谷    低功耗    正在生成               [暂停] [取消]

┌──────────────────────────────────────────────────────────────┐
│ [封面] 山谷                                                   │
│        源文件          自动平衡            低功耗             │
│        4K · 240 FPS    2K · 120 FPS        2K · 60 FPS       │
│        576 MB          已完成 · 820 MB     生成中 · 42%       │
│        只读信息         [•••]               [取消]             │
└──────────────────────────────────────────────────────────────┘
```

页面只显示有视频源、生成任务或已有副本的媒体；静态图片不进入该页面。

每个媒体卡片包含：

- 封面、名称和所属分组。
- 源文件的分辨率、帧率、编码和大小。选中后只删除源文件，必须单独确认并移入 Windows 回收站；封面、名称、元数据和已有副本继续保留。
- 自动平衡副本的目标规格、状态、大小和操作。
- 低功耗副本的目标规格、状态、大小和操作。
- 每行的“源文件 / 自动平衡 / 低功耗”使用复选控件；自动平衡和低功耗可以同时选择并一次删除。
- 源文件与两类副本独立选择。删除源文件时至少保留一个完整、可播放的优化副本；删除最后一个可播放文件的操作必须被阻止。
- 未选择任何文件时右侧删除按钮保持禁用，避免整行误删。
- 当前实际正在使用的文件用一个轻量强调边框或小圆点标识，不堆叠说明文字。

副本状态限定为：

- 未生成
- 排队中
- 等待接通电源
- 生成中（百分比）
- 已暂停
- 已完成
- 过期
- 失败

生成进度通过 FFmpeg `-progress` 的 `out_time_us` 与源媒体时长计算，并限制在 0～100%。切换到下一编码后端时从 0 重新计量；输出完成最终校验前最多显示 99%，只有完整副本验收成功才显示完成。每个媒体目录用 `.optimization-progress` 保存 `queued`、`waiting-power`、`generating` 或 `paused` 状态；已知进度时同时保存百分比。为避免频繁写盘，仅在百分比变化且距上次持久化至少 1 秒时更新；写入后会重新核对取消、暂停、抑制及替代请求的持久状态，失去所有权的旧任务会立即清理自己的进度，成功、失败或取消后也会清理进度文件。

操作按状态显示：

- 未生成：生成。
- 排队中、等待电源、生成中：暂停或取消。
- 已暂停：继续或取消；继续会从头生成，避免复用不可校验的 MP4 半成品。
- 已完成、过期、失败：选中该档副本后删除；删除标记会阻止后台立即重建，手动点“生成”才恢复。
- 源文件：选中后只把源视频移入回收站，保留封面、名称、元数据和已有副本；随后原画选择和副本重新生成入口变为不可用。

### 页面宽度适配

- 宽窗口使用“源文件 / 自动平衡 / 低功耗”三列对比。
- 窄窗口将三列改为同一媒体卡片内的纵向区块，不使用水平滚动。
- 页面不提供搜索框；数量较多时使用虚拟化列表，并可在以后增加简单状态筛选。

### 代码结构建议

当前 `MainWindow` 只有 `SettingsPage` 和 `WallpaperPage` 两种可见页面。新增页面时不继续堆叠零散的 `Visibility` 判断，改为统一导航状态：

```cpp
enum class AppPage
{
    settings,
    variants,
    wallpaperGroup,
};
```

由一个 `Navigate(AppPage, optionalGroupId)` 负责页面显隐、侧边栏选中状态和数据刷新。副本页面的数据读取、任务命令和 UI 模型放入独立的 `VariantLibraryViewModel` 或等价控制器，不能继续扩大 `MainWindow.xaml.cpp`。

## 验收清单

- 三个档位在插电和电池供电时语义一致。
- 60 Hz 显示器不会生成 120 FPS 自动平衡副本。
- 低分辨率或低帧率源文件不会被放大或插帧。
- 4K 60 FPS 源视频在 2K 低功耗目标下能够生成 2K 60 FPS 副本。
- 同一媒体跨不同分辨率显示器时只生成最高必要规格并共享解码。
- NVIDIA、AMD、Intel 单卡，核显 + 独显，以及同厂商双卡布局都按具体 LUID/DXGI 适配器选择解码与编码路径；一条显示路由降级不得改变其他路由的画质副本。
- 无可用硬件解码或编码器的低配机器只在可控分辨率/帧率上为非 HDR 的 SDR 素材生成 8-bit SDR H.264 `cpu-smooth` 副本；普通 SDR 10-bit 允许转换，HDR、BT.2020 或带 HDR 色彩标记的高位深素材必须跳过，且源文件始终不变。
- 快速切换档位只留下最终任务，不产生多个 `.part` 文件。
- 生成进度单调反映当前编码后端的已处理媒体时间，后端重试会归零，最终校验通过前不会提前显示 100%。
- 新副本首帧到达前旧画面持续存在。
- UI 明确区分“源文件”“当前副本”“过期副本”和总占用，不能把多个文件显示成一个副本。
