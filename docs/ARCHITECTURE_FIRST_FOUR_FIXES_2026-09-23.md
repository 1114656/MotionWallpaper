## 多屏进程退役

按显示目标保存最近确认成功的路由。某屏完成交接就可退役它不再需要的旧路由，不再等待另一块屏幕成功。未确认的中间候选被新请求替代时停止；每个显示目标只保留一个已确认前驱，交接最多保留 12 秒。停止失败仍保留进程句柄和播放租约，后续继续确认退出，不提前删除被使用的文件。

纯策略回归覆盖“一屏持续失败、另一屏成功切换”、连续 50 次替换未成功候选、退役期限、热拔屏和停止后的清理。它不是对真实坏驱动或双显卡故障注入的认证。

## 播放健康检测与有界恢复

Renderer 的窗口线程每秒发送带目标 revision 的播放进度，序号取全部输出共同达到的进度。消息循环阻塞会停止心跳；循环仍活着但输出不再推进会只剩相同序号。Agent 仅对已确认且应播放的视频检查，不把暂停、冻结或静态图片当作播放故障。

心跳失联 10 秒触发恢复，画面无进度通常为 15 秒；低帧率视频按源帧周期放宽判断。旧目标的心跳不能刷新新目标的期限。五分钟内第三次健康故障停止自动恢复，保留具体错误并允许用户重试；正常进程崩溃仍使用原有退避策略。原画模式继续遵循既有失败提示流程，故障会交由用户重试或选择生成副本，不绕过原画失败提示。

协议兼容 Windows CRLF，数值及消息长度受限。回归覆盖有心跳无帧、无心跳、过期 revision、低帧率、无效消息与恢复预算；真实隐藏 Renderer 验证 CPU 和自动路径都在首帧后持续报告推进的输出序号。

## 帧时序

使用 QPC 单调时钟计算目标期限，以 100 ns 单位保存帧周期。帧传输和呈现耗时包含在本帧预算里，完成后只等待距下一期限的剩余时间。错过期限跳至未来时刻，不突发追赶积压帧。软件上限继续受原有 governor 控制，不将 60 FPS 简化为处理后再等待 17 ms。

纯时序回归覆盖连续 600 帧带 3 ms 处理成本、漏过多个期限、周期变化和 59.94 FPS 精度。真实隐藏消息窗口使用可测量的 3 ms CPU 负载与高精度计时器验证间隔。该测试证明调度节拍，不等于认证任何显卡的最终扫描帧率。

## 副本清晰度与缓存

副本按当前居中铺满规则先裁切、再缩放到目标尺寸。平衡档的 3840×2160 源用于 3440×1440 屏幕时生成 3440×1440；用于 1080×1920 竖屏时生成 1080×1920。源像素不足则降低输出尺寸，保持不在转码阶段放大的约束。节能仍受最高 1080p 的对应横竖屏尺寸限制。

FFmpeg 的自动旋转先于裁切；裁切使用实际输入帧尺寸、偶数色度边界，最终设置方形像素。SDR/HDR 色彩转换契约沿用上一批，不改写源文件。

相同比例屏幕可按最大需要尺寸/帧率共用副本；不同比例分开选择，避免用横屏宽度与竖屏高度合成错误的正方形目标。准备任务会先选择尚缺的比例，避免一个已完成的横屏副本反复取消竖屏任务。

新副本使用 v7 缓存身份。v6 文件保留；只有源/目标宽高比完全一致且通过既有规格、色彩及可播放性验证时才直接复用，避免普通 16:9 视频在升级后无谓重转。比例变化的旧副本不冒充新的裁切结果。
